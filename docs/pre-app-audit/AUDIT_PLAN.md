# خطة المراجعة النهائية لـ Loopz قبل React Native / Expo

الحالة: معتمدة مبدئياً من أحمد  
النطاق: مراجعة شاملة للموقع والبنية والبيانات قبل بدء التطبيق  
قاعدة العمل: ChatGPT يراجع ويتحقق فقط، وClaude ينفذ التعديلات بعد تسجيلها واعتمادها

## هدف المراجعة

الوصول إلى قرار موثق من ثلاث نتائج فقط:

- `GO`: جاهز للبدء في تطبيق Expo.
- `GO WITH CONDITIONS`: جاهز مع عناصر معلقة منخفضة الخطورة ومقبولة من أحمد.
- `NO-GO`: توجد مخاطر أو عوائق تمنع التحويل الآمن.

## درجات الخطورة

| الدرجة | التعريف |
|---|---|
| P0 | تسريب بيانات، تجاوز صلاحيات، فقد بيانات، سر مكشوف، أو توقف كامل |
| P1 | وظيفة أساسية مكسورة، خطر أمني مرتفع، أو أداء يمنع الاستخدام |
| P2 | مشكلة مهمة لها بديل مؤقت ولا تمنع المسار الأساسي |
| P3 | تحسين أو تنسيق أو تجربة استخدام غير حرجة |

## حالات المهمة

`TODO` → `IN_PROGRESS` → `READY_FOR_REVIEW` → `VERIFIED` → `ACCEPTED`

وحالات الاستثناء:

- `BLOCKED`: مانع يحتاج قراراً أو صلاحية.
- `CHANGES_REQUESTED`: التنفيذ لم يحقق معيار القبول.
- `DEFERRED`: مؤجل بقرار أحمد مع سبب وتاريخ مراجعة.

- Cold start وWarm resume.
- وقت ظهور المحتوى الأساسي.
- التنقل بين التبويبات.
- صفحات الأعمال والملفات.
- القوائم الطويلة والتمرير.
- Trailers وتشغيل الفيديو.
- البحث أثناء الكتابة.
- رفع الصور.
- الطلبات المتكررة والمكررة.
- أحجام الصور والفيديو والاستجابات.
- استهلاك الذاكرة وتسربها.
- إعادة الرسم غير الضرورية.
- N+1 والاستعلامات البطيئة.
- Bundle size وDynamic imports.
- Caching وPrefetch.
- أداء البيانات الحقيقية وليس Mock data.

### أهداف الويب

- LCP ≤ 2.5s.
- INP ≤ 200ms.
- CLS ≤ 0.1.
- القياس عند p75.
- استجابة تفاعل مرئية خلال 100ms قدر الإمكان.
- هدف API العادي المبدئي: p95 أقل من 800ms.
- الصفحات الثقيلة: p95 أقل من 1.5s ما لم يوجد استثناء موثق.
- صفر JavaScript errors في الرحلات الحرجة.

### الأجهزة والشبكات

- iPhone Safari وPWA.
- Android متوسط أو منخفض المواصفات.
- Chrome وSafari وEdge.
- جوال صغير وكبير وTablet وDesktop.
- Wi-Fi و4G بطيء وانقطاع أثناء العملية.

### معيار القبول

- تحقيق الميزانية المتفق عليها أو توثيق الاستثناء.
- لا Scroll jank مؤثر ولا Flicker في المسارات الأساسية.
- لا تسرب ذاكرة واضح بعد التنقل المتكرر.

## المرحلة 11: بوابة القرار النهائي

لا يسمح ببدء بناء Expo حتى يتحقق:

- صفر P0 وP1.
- صفر ثغرات حرجة أو مرتفعة.
- RLS يغطي 100% من الجداول المكشوفة.
- نجاح الرحلات الحرجة.
- لا أسرار في الملفات أو تاريخ Git.
- لا أخطاء Console غير معالجة في الرحلات الحرجة.
- تحقيق أهداف الأداء أو اعتماد الاستثناءات.
- اكتمال العربية والإنجليزية والثيمات.
- نجاح الجولات التعريفية.
- توثيق حفظ البيانات والنسخ والتعافي.
- تنظيف العناصر الميتة المعتمدة.
- API وطبقة بيانات قابلة للموبايل.
- اكتمال توافق الحزم مع Expo.
- توثيق ما سيشارك وما سيعاد بناؤه.

## المخرجات النهائية

1. خريطة الصفحات والميزات.
2. سجل الأخطاء الموحد.
3. تقرير الأمن والصلاحيات.
4. تقرير Supabase والبيانات والخصوصية.
5. تقرير الأداء.
6. تقرير التصميم والمحتوى والجولات.
7. تقرير تنظيف الملفات والكود.
8. تقرير التشغيل والتعافي.
9. مصفوفة React Native / Expo.
10. تقرير GO / GO WITH CONDITIONS / NO-GO.
