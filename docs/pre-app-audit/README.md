# Loopz Pre-App Audit

هذا المجلد هو المرجع الرسمي لمراجعة Loopz قبل بدء بناء تطبيق React Native / Expo.

## الملفات

- [AUDIT_PLAN.md](./AUDIT_PLAN.md): خطة المراجعة الكاملة ومراحل القبول.
- [SHARED_PROGRESS.md](./SHARED_PROGRESS.md): ملف المتابعة المشترك وتبادل الأدوار بين ChatGPT وClaude.
- [CLAUDE_HANDOFF.md](./CLAUDE_HANDOFF.md): تعليمات البدء والتنسيق الموجهة إلى Claude.

## الأدوار

- **المالك:** أحمد — خارج دورة الاعتماد التشغيلية اليومية.
- **المراجع والبوابة التقنية:** ChatGPT — قراءة، تحقق، اختبارات غير مغيرة، تسجيل النتائج، واعتماد أو إعادة تنفيذ Claude.
- **المنفذ:** Claude — تعديل الكود والاختبارات والإعدادات وفق المهام المسجلة ثم تقديم الأدلة.
- **المرجع المشترك:** `SHARED_PROGRESS.md`.

## سياسة العمل المستقل

1. لا تعديل مباشر على `main` أثناء التدقيق.
2. لا يحتاج Claude الرجوع إلى أحمد في الإصلاحات العادية أو حذف كود ميت مثبت على فرع العمل.
3. يبدأ Claude بعد وجود مهمة ومعيار قبول، ويضع `READY_FOR_REVIEW`.
4. يراجع ChatGPT التنفيذ؛ عند النجاح يضع `VERIFIED` ويجيز الدمج في فرع المراجعة الموحد.
5. يبقى `main` وProduction ثابتين حتى اجتياز بوابة التدقيق النهائية.
6. التغييرات الإضافية القابلة للرجوع في قاعدة البيانات تُختبر على Staging أولاً.
7. أي حذف بيانات Production أو Migration تدميرية غير محددة الهدف لا تشملها موافقة مفتوحة، وتُوقف عند ظهورها لتحديد الهدف وخطة الاسترجاع.
8. اختبارات الأمن النشطة تكون على Preview أو Staging فقط.
9. يمنع وضع أسرار أو Tokens أو بيانات مستخدمين في التوثيق أو السجلات.
10. لكل مشكلة رقم `LOOPZ-AUD-0001`، ولا تغلق إلا بعد تحقق ChatGPT.

## التنسيق

- تحديثات Claude تكون في `SHARED_PROGRESS.md` كل 10 دقائق كحد أقصى أثناء عمله النشط.
- التنبيه إلى ChatGPT يكون من خلال Pull Request عند Commit أو Comment؛ وهو أسرع من الفحص المجدول.
- يجب قراءة أحدث نسخة قبل كل تحديث لتجنب التعارض.
