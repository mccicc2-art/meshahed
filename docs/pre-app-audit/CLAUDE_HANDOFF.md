# Claude Handoff — Loopz Pre-App Audit

## الرسالة الموجهة إلى Claude

أنت المنفذ في مراجعة Loopz النهائية قبل بدء تطبيق React Native / Expo، وChatGPT هو المراجع الخارجي. أحمد هو صاحب القرار النهائي.

المستودع:

- `mccicc2-art/meshahed`
- الموقع: `https://loopztv.com`
- فرع التوثيق والتنسيق: `docs/pre-app-audit`
- مجلد العمل: `docs/pre-app-audit/`

ابدأ بقراءة الملفات التالية كاملة:

1. `docs/pre-app-audit/README.md`
2. `docs/pre-app-audit/AUDIT_PLAN.md`
3. `docs/pre-app-audit/SHARED_PROGRESS.md`
4. هذا الملف.

## تقسيم الأدوار

### ChatGPT

- يقرأ ويفحص ويختبر فقط.
- يسجل المشكلات ومعيار القبول.
- يراجع Diff ونتائج الاختبارات.
- هو الطرف الذي يضع VERIFIED.
- لا يكتب كود التطبيق ولا ينفذ إصلاحات.

### Claude

- ينفذ فقط المهام المسجلة والواضحة.
- يعمل في فرع مستقل لكل مجموعة إصلاحات.
- يقدم Commit SHA والاختبارات والأدلة.
- يضع READY_FOR_REVIEW ولا يضع VERIFIED.
- لا يدمج ولا ينشر ولا ينفذ Migration على Production دون موافقة أحمد.

## قواعد غير قابلة للتجاوز

- لا تعديل مباشر على `main`.
- لا Merge أو Deploy أو Migration أو حذف ملفات دون موافقة أحمد.
- لا تطوير ميزات جديدة أثناء جولة التدقيق.
- اختبارات الأمن النشطة على Preview أو Staging فقط.
- لا Secrets أو Tokens أو بيانات مستخدمين في الردود أو الملفات.
- لا حذف كود ميت قبل إثبات عدم استخدامه وتسجيله ومراجعته.
- كل مشكلة تحمل رقم `LOOPZ-AUD-XXXX`.
- المرجع الوحيد للحالة هو `SHARED_PROGRESS.md`.

## التنسيق كل 10 دقائق

أثناء جلسة العمل النشطة:

1. اقرأ أحدث نسخة من `SHARED_PROGRESS.md`.
2. حدّث قسم `Claude Check-in` خلال 10 دقائق كحد أقصى أو عند كل إنجاز مهم.
3. سجل ما تم وما يجري والموانع والأدلة.
4. غيّر `صاحب الدور التالي` إلى ChatGPT عند اكتمال ردك.
5. استخدم Commit:
   `audit(coord): claude check-in YYYY-MM-DD HH:MM UTC`
6. لا تعدل الملف بالتزامن مع ChatGPT.
7. إذا لم يكن ChatGPT مشغلاً، اترك الدور بانتظاره ولا تفترض أن هناك اتصالاً تلقائياً.

## المهمة الأولى فقط: Phase 0 Baseline

لا تصلح أي شيء الآن. المطلوب جرد وتوثيق:

- SHA الحالي لـ `main`.
- حالة الفروع أو التغييرات القائمة ذات الصلة.
- إصدارات Node وNext.js وReact وTypeScript والحزم الأساسية.
- Scripts المتاحة للفحص والبناء والاختبار.
- بيئات Local وPreview وProduction المعروفة دون كشف القيم.
- آخر Deploy أو Build معروف إن كان الوصول متاحاً.
- الأدوار وحسابات الاختبار المطلوبة.
- أي مانع يمنع بدء التدقيق.
- اقتراح أوامر Read-only للمرحلة التالية، دون تشغيل أمر مغير.

بعدها:

- حدّث `SHARED_PROGRESS.md`.
- ضع الحالة `READY_FOR_REVIEW`.
- سلّم الدور إلى ChatGPT.
- توقف عن التقدم إلى Phase 1 حتى تأتي مراجعة ChatGPT.
